可合法获取的官方与开放数据清单

把「能抓什么、从哪抓、能不能商用」讲清楚——每类百科背后都该有一份可追溯的数据来源表。

开放数据API官方数据源爬取合规WikidataNMPA

概览

这份清单回答一个具体问题：本站的球队、色号、酒店与百科专题，哪些内容可以从官方或开放渠道自动获取，哪些只能人工整理。收录标准有三条——来源可识别、字段可结构化、使用条件可说明。

数据源分成三档。第一档是官方机构直接提供的数据（如 NBA 官网统计、国家药监局注册备案查询），字段最权威但接口未必公开；第二档是开放数据库（如 Wikidata、Open Beauty Facts），有明确许可证与批量导出；第三档是行业榜单与权威媒体（如《HOTELS》榜单、中国旅游饭店业协会报告），多为定期发布的非结构化资料。

重要边界：大量网站并不提供公开 API。通过页面抓取得到的数据，必须遵守对方服务条款、robots.txt 与当地法规；商业用途尤其需要核对授权。本站现有 1000+ 条球队与色号数据为依据公开知识人工整理的结构化档案，并未直接调用下列任何接口，色块均为示意。

足球：官方与开放数据源

足球是开放数据最成熟的项目。注意「免费层」通常只覆盖顶级联赛、且有每分钟请求上限。

来源类型可获取内容接入与口径许可/限制
football-data.org v4第三方聚合 APIcompetitions / teams / matches / standings / scorers / squad；Team 下用 Person 表示球员、教练、裁判REST + JSON，API Token 放请求头；按 competition、season、matchday、date 过滤；v4 中 dateTo 为排他边界有免费层与付费层；免费额度与限流以官网当前说明为准
The Sports DB开放社区库球队、联赛、赛程、球员、奖杯、队徽图片提供免费测试 key（如 3）与 JSON API数据为社区维护，需交叉核对；图片另有版权
各联赛/俱乐部官网一手官方赛程、积分、阵容、公告、俱乐部历史多为页面或新闻稿，无统一 API；需按 robots.txt 与条款判断是否可抓取版权与数据库权利归官方，通常不允许整体转载

注：优先顺序建议：官方榜单核对 → Wikidata 建实体 → API 补赛程与统计。

篮球：官方统计与开放接口

NBA 官网统计是最完整的篮球数据源，但官方并未提供面向公众的稳定 API 文档。

来源类型可获取内容接入与口径许可/限制

CBA 官网 / 中国篮协官方球队名单、赛程、积分、球员注册信息以网页公告与数据页面为主；无统一公开 API以官网当前发布为准，转载需注明来源
Basketball Reference权威统计站历史赛季、球队与球员档案、荣誉适合人工核对与引用；页面结构稳定但无官方 API站点内容受版权保护，避免整站抓取

口红与化妆品：备案、成分与色号

这是最容易被误判的领域：官方监管库有产品备案，但不提供「色号色值」；色值需来自品牌或开放美妆库。

来源类型可获取内容接入与口径许可/限制
国家药监局（NMPA）化妆品注册备案查询官方监管库国产/进口化妆品注册与备案、备案编号、备案人、生产企业、成分信息官网「化妆品—化妆品查询」栏目；也可通过「化妆品监管」App、国务院客户端小程序扫码查询面向公众查询，非公开批量 API；编号规则可用于识别普通/特殊化妆品
Open Beauty Facts开放数据库条码、品牌、产品名、INCI 全成分、成分数、类别、标签、规格、开封保质期、原产国、图片、vegan/无棕榈油分析单品 API：/api/v2/product/{barcode}.json；批量用 MongoDB dump、JSONL、Parquet、CSV、近 14 天 deltaODbL（数据库）/ DbCL（内容）/ CC BY-SA（图片）；必须署名，改编库需同许可公开；禁止用 API 抓全库，全量请用导出文件
品牌官网（MAC / Dior / YSL 等）一手官方色号名、色号编号、色调描述、质地、价格、官方色卡图多为商品页，需按页面结构与条款判断是否可抓取色卡图片与文案受版权保护；色值需人工取样且受屏幕与光线影响
电商与零售平台商业来源在售色号、价格、用户评价通常有严格反爬与条款限制不建议作为主要数据源；如需商用应走官方合作或授权 API

注：本站 220 支色号为人工整理的示意数据，色调与色块不代表品牌官方色值。

酒店：集团规模与品牌矩阵

酒店行业没有统一开放 API，权威信息主要来自年度榜单、协会报告与集团财报。

来源类型可获取内容接入与口径许可/限制

官方数据不等于开放数据

官网能查到，只说明人类可读；机器可批量获取，还需要 API、导出文件或明确许可。

官方查询

NMPA、NBA Stats、ATP 官网都能查，但多数没有面向公众的稳定批量接口。

开放数据库

Wikidata、Open Beauty Facts 有许可证与批量导出，适合做结构化基础。

组合使用

用开放库建实体，用官方页面核对关键字段，用行业榜单补规模数据。

一句话记住：开放库负责规模，官方源负责校验。

为什么口红色号最难得「准确」

监管库管的是产品合规身份，品牌页面管的是营销命名，二者并不共享「色值」字段。

监管口径

备案编号证明产品合法上市，但同一备案下可能有多个色号。

品牌口径

色号名与编号由品牌自定义，跨品牌不可直接比较，「#12」在各家不是同一个颜色。

显示口径

屏幕色值受设备、光线与质地影响，官方色卡也只是参考。

一句话记住：色号库能可靠记录名称与质地，色值只能标注为示意。

合规抓取的最小清单

在写第一行爬虫代码之前，先把这五件事记进笔记，能避开绝大多数麻烦。

条款与 robots

确认允许自动化访问；遵守 Disallow 与 Crawl-delay。

许可与署名

ODbL、CC BY-SA、CC BY-NC 的义务完全不同，商用前逐条核对。

结构化优先

有 API 或 dump 就不抓 HTML；有批量导出就不压接口。

一句话记住：能合法稳定拿到的数据，才是好数据。

按需求选源的决策表

先问自己要什么，再决定从哪拿。

要实时比分与赛程

用 API 类：football-data.org、ESPN、BALLDONTLIE；免费层通常限联赛与频率。

要历史与人物档案

用开放库：Wikidata + Wikipedia + 各项目开放 CSV；适合批量建实体。

要产品合规信息

用官方监管库：NMPA 注册备案查询、国家统计局；拿编号与备案主体，不拿色值。

要成分与条码

用 Open Beauty Facts：ODbL 许可，可 API 单查，也可下载每日全量导出。

要行业规模排名

用年度榜单与财报：《HOTELS》、协会报告、集团投资者关系页；务必统一截止日与口径。

抓取前必须确认的五件事

这一步比写代码更重要。

服务条款

是否允许自动化访问、是否允许二次发布、是否允许商用。

robots.txt

检查目标路径是否被 Disallow，遵守 Crawl-delay。

许可证

ODbL/CC BY-SA 需要署名与同许可共享；CC BY-NC 禁止商业使用。

结构化替代

优先用 API、批量导出、开放数据，而不是逐页 HTML 抓取。

频率与缓存

控制请求频率、设置缓存与 User-Agent；全量需求用 dump，不压 API。

速查口诀

  1. 选源口诀：官方看权威，开放库看许可，榜单看口径，聚合 API 看额度。
  2. 合规口诀：先看条款、再看 robots、最后看许可证；不确定就别批量抓。
  3. Open Beauty Facts 口诀：单品查 API，全量下 dump；ODbL 要署名，改编要开源。
  4. 体育口诀：实时用 API，历史用 CSV，人物机构用 Wikidata。
  5. 酒店口诀：规模看客房数，营收看财报，品牌矩阵看官网，排名看 HOTELS。
